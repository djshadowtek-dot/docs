title: "Quickstart: Run Your First Google Infrastructure Instance"
sidebarTitle: "Quickstart"

---

This quickstart walks you through creating a Google Infrastructure account, installing the `gcloud` CLI, authenticating, launching a virtual machine instance, connecting to it over SSH, and cleaning up — all in under ten minutes. By the end you will have hands-on familiarity with the core provisioning workflow you will use for every resource type on the platform.

<Tip>
  New accounts receive free trial credits that cover the cost of running the instance in this guide. No charges are incurred until your credits are exhausted and you have explicitly enabled billing. Visit [console.cloud.google.com/billing](https://console.cloud.google.com/billing) to review your credit balance at any time.
</Tip>

<Steps>
  <Step title="Create Your Account">
    Navigate to [console.cloud.google.com](https://console.cloud.google.com) and sign in with a Google account. If this is your first visit, accept the terms of service and complete the account setup wizard.

    Once you are in the console, create a new project:

    1. Click the project selector in the top navigation bar.
    2. Select **New Project**.
    3. Enter a project name such as `my-first-project` and click **Create**.

    Note the **Project ID** shown beneath the project name — you will use it in subsequent steps.

    <Note>
      Every Google Infrastructure resource lives inside a project. Projects are also the boundary for quotas, billing, and IAM policies. New projects start with default quota limits; you can request increases from the **IAM & Admin › Quotas** page in the console once your project is active.
    </Note>
  </Step>

  <Step title="Install the CLI">
    The `gcloud` CLI is the primary command-line tool for managing Google Infrastructure resources. Install it on your local machine using the instructions for your operating system.

    <CodeGroup>
      ```bash macOS
      # Install via the official interactive installer
      curl https://sdk.cloud.google.com | bash

      # Restart your shell, then initialize the CLI
      exec -l $SHELL
      gcloud init
      ```

      ```bash Linux
      # Add the Cloud SDK distribution URI as a package source
      echo "deb [signed-by=/usr/share/keyrings/cloud.google.gpg] \
        https://packages.cloud.google.com/apt cloud-sdk main" \
        | sudo tee /etc/apt/sources.list.d/google-cloud-sdk.list

      # Import the Google Cloud public key
      curl https://packages.cloud.google.com/apt/doc/apt-key.gpg \
        | sudo apt-key --keyring /usr/share/keyrings/cloud.google.gpg add -

      # Update and install the SDK
      sudo apt-get update && sudo apt-get install -y google-cloud-cli

      # Initialize the CLI
      gcloud init
      ```

      ```powershell Windows
      # Download and run the Windows installer
      # Navigate to https://cloud.google.com/sdk/docs/install#windows
      # and download GoogleCloudSDKInstaller.exe, then run it.

      # After installation completes, open a new PowerShell window and run:
      gcloud init
      ```
    </CodeGroup>

    After running `gcloud init`, the CLI opens a browser window to complete the authentication flow. Follow the prompts and return to your terminal once authentication succeeds.
  </Step>

  <Step title="Authenticate">
    Authenticate your local environment and point the CLI at the project you created in Step 1.

    ```bash
    # Log in with your Google account
    gcloud auth login

    # Set the active project (replace PROJECT_ID with your actual project ID)
    gcloud config set project PROJECT_ID
    ```

    Confirm that both settings are correct:

    ```bash
    gcloud config list
    ```

    The output shows your active account and project. All subsequent `gcloud` commands target this project unless you override it with the `--project` flag.
  </Step>

  <Step title="Create Your First Instance">
    Create a virtual machine instance in the `us-central1-a` zone using the `e2-standard-4` machine type, which provides 4 vCPUs and 16 GB of memory.

    ```bash
    gcloud compute instances create my-instance \
      --zone=us-central1-a \
      --machine-type=e2-standard-4 \
      --image-family=debian-12 \
      --image-project=debian-cloud
    ```

    The command returns a table confirming the instance name, zone, machine type, internal IP, and external IP once the instance reaches `RUNNING` status. This typically takes 20–30 seconds.

    To list all running instances in your project:

    ```bash
    gcloud compute instances list
    ```
  </Step>

  <Step title="Connect to Your Instance">
    Open an SSH session to your new instance directly from the CLI. The `gcloud compute ssh` command handles key generation and firewall rules automatically on first use.

    ```bash
    gcloud compute ssh my-instance --zone=us-central1-a
    ```

    You are now logged in to the instance. Run a quick sanity check to confirm the environment:

    ```bash
    uname -a
    nproc
    free -h
    ```

    Type `exit` to close the SSH session and return to your local shell.

    <Tip>
      You can also connect to instances from the console by navigating to **Compute Engine › VM Instances** and clicking **SSH** in the instance row. This launches a browser-based terminal with no local key configuration required.
    </Tip>
  </Step>

  <Step title="Clean Up">
    Delete the instance to stop incurring charges once you are finished exploring.

    ```bash
    gcloud compute instances delete my-instance --zone=us-central1-a
    ```

    The CLI prompts you to confirm. Type `Y` and press Enter. The instance and its attached boot disk are permanently deleted within a few seconds.

    <Warning>
      Deleting an instance also deletes its boot disk unless you created the disk separately with `--no-boot-disk-auto-delete`. Back up any data you need before running this command.
    </Warning>
  </Step>
</Steps>
